# Data Model

## SQLite (`SENTINEL_DB_PATH`, default `data/sentinelstream.db`)

Created in Phase 3. After Phase 3 the schema changes only with human approval.

Conventions: timestamps are ISO-8601 UTC strings with milliseconds (`2026-10-28T10:15:30.123Z`). Alert and flow IDs are UUID4 hex strings generated by the inference thread, so the WebSocket message and the database row share the same ID before the batched insert happens. WAL mode is enabled so API reads do not block the writer.

### `alerts`

| Column | Type | Constraints | Notes |
|---|---|---|---|
| `id` | TEXT | PRIMARY KEY | UUID4 hex |
| `timestamp` | TEXT | NOT NULL | Flow end time (last packet seen) |
| `src_ip` | TEXT | NOT NULL | Forward-direction source (first packet's sender) |
| `dst_ip` | TEXT | NOT NULL | |
| `src_port` | INTEGER | NOT NULL | `0` for ICMP / no-port protocols |
| `dst_port` | INTEGER | NOT NULL | `0` for ICMP / no-port protocols |
| `protocol` | TEXT | NOT NULL, CHECK IN (`TCP`,`UDP`,`ICMP`,`OTHER`) | |
| `attack_type` | TEXT | NOT NULL | See [attack types](#attack-types) |
| `confidence` | REAL | NOT NULL, CHECK 0 ≤ x ≤ 1 | See [ARCHITECTURE.md](ARCHITECTURE.md#detection-logic) |
| `severity` | TEXT | NOT NULL, CHECK IN (`low`,`medium`,`high`) | Derived from confidence |
| `batch_id` | INTEGER | NULL, FK → `upload_batches.id` | NULL for live capture |
| `flow_id` | TEXT | NULL, FK → `flows.id` | Added at the user's request (Phase 0) so an analyst can open the features behind an alert |

Indexes: `timestamp DESC`, `severity`, `attack_type`, `batch_id`.

### `flows`

Stores the features of every flow that produced an alert (not every flow seen), so the DB grows with alerts, not with traffic.

| Column | Type | Constraints | Notes |
|---|---|---|---|
| `id` | TEXT | PRIMARY KEY | UUID4 hex |
| `flow_key` | TEXT | NOT NULL | `PROTO\|src_ip\|src_port\|dst_ip\|dst_port` (forward direction), e.g. `TCP\|127.0.0.1\|54321\|127.0.0.1\|22` |
| `feature_json` | TEXT | NOT NULL | JSON object, keys = feature names in model order |
| `created_at` | TEXT | NOT NULL | When the row was written |

Index: `flow_key`.

### `upload_batches`

| Column | Type | Constraints | Notes |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | Created synchronously by `POST /upload-pcap` |
| `filename` | TEXT | NOT NULL | Client filename, truncated to 255 chars. Display only; never used as a path |
| `uploaded_at` | TEXT | NOT NULL | |
| `status` | TEXT | NOT NULL, CHECK IN (`pending`,`processing`,`done`,`failed`) | |

Write order: `flows` row before the `alerts` row that references it, in the same transaction.

## Attack types

`attack_type` is one of:

| Value | Source |
|---|---|
| `anomaly` | Isolation Forest only (no supervised label) |
| `DoS`, `DDoS`, `PortScan`, `BruteForce`, `WebAttack`, `Bot`, `Infiltration`, `Heartbleed` | Random Forest (Phase 5), grouped from CICIDS2017 labels below |

`BENIGN` is a training label and is never stored as an alert.

Planned CICIDS2017 label grouping (finalised in Phase 5):

| CICIDS2017 label(s) | `attack_type` |
|---|---|
| DoS Hulk, DoS GoldenEye, DoS slowloris, DoS Slowhttptest | `DoS` |
| DDoS | `DDoS` |
| PortScan | `PortScan` |
| FTP-Patator, SSH-Patator | `BruteForce` |
| Web Attack – Brute Force, Web Attack – XSS, Web Attack – Sql Injection | `WebAttack` |
| Bot | `Bot` |
| Infiltration | `Infiltration` |
| Heartbleed | `Heartbleed` |

## Shared feature subset

Defined once in `backend/features/feature_set.py`. Order matters: it is the column order of every model input.

| # | Feature | Live computation (from packets) | CICIDS2017 CSV column(s) |
|---|---|---|---|
| 1 | `flow_duration_s` | last packet time − first packet time | `Flow Duration` (µs) ÷ 1,000,000 |
| 2 | `fwd_packets` | packets from the forward-direction sender | `Total Fwd Packets` |
| 3 | `bwd_packets` | packets in the reverse direction | `Total Backward Packets` |
| 4 | `total_bytes` | sum of transport payload lengths, both directions | `Total Length of Fwd Packets` + `Total Length of Bwd Packets` |
| 5 | `packets_per_s` | (fwd + bwd) ÷ duration, zero-duration rule applies | `Flow Packets/s` |
| 6 | `syn_count` | TCP packets with SYN set | `SYN Flag Count` |
| 7 | `ack_count` | TCP packets with ACK set | `ACK Flag Count` |
| 8 | `fin_count` | TCP packets with FIN set | `FIN Flag Count` |
| 9 | `rst_count` | TCP packets with RST set | `RST Flag Count` |

CICIDS2017 CSV column names have leading spaces; cleaning strips them before mapping. The zero-duration rule (how `packets_per_s` is defined when duration is 0) is written once in `feature_set.py` and applied to both CSV and live features. These features only approximate CICFlowMeter's; see [LIMITATIONS.md](LIMITATIONS.md).

### Flows (runtime)

- Key: 5-tuple (`src_ip`, `dst_ip`, `src_port`, `dst_port`, `protocol`), bidirectional. The first packet's sender defines the forward direction.
- Export: idle timeout 5 s, active timeout 10 s (a long-lived flow is scored every 10 s), or TCP FIN/RST from both sides. Checked on a 1-second tick. Values are initial and documented as a limitation.

## Model artifacts (`models/`)

Each model is saved as two files side by side:

```
models/isolation_forest.joblib
models/isolation_forest.features.json
models/random_forest.joblib
models/random_forest.features.json
```

`<name>.features.json`:

```json
{
  "model": "isolation_forest",
  "feature_order": ["flow_duration_s", "fwd_packets", "bwd_packets", "total_bytes",
                    "packets_per_s", "syn_count", "ack_count", "fin_count", "rst_count"],
  "trained_on": ["data/raw/cicids2017/Monday-WorkingHours.pcap_ISCX.csv"],
  "n_train_rows": 0,
  "sklearn_version": "x.y.z",
  "random_state": 42,
  "created_at": "2026-10-28T10:15:30.123Z"
}
```

Inference refuses to load a model whose `feature_order` differs from `feature_set.py`.
