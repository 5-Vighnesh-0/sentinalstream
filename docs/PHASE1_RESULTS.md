# Phase 1 Results — Offline detection (hardened)

Every number below comes from the commands in [Reproduce](#reproduce) and matches `data/phase1_detections.csv`. This is a smoke test of the pipeline on one small synthetic PCAP, not a benchmark; accuracy and false-positive rates are measured in Phase 5 (CICIDS2017, all days) and Phase 2 (alerts per hour on real loopback use).

## Detectors

| Detector | What it flags | Output |
|---|---|---|
| Isolation Forest (committed `models/isolation_forest.joblib`) | TCP/UDP flow whose anomaly score > 99th percentile of benign training scores | `anomaly`, `source=isolation_forest`, severity `low`/`medium` (never `high`, D6) |
| Port-scan rule (`backend/detection/scan_rule.py`) | ≥ 20 distinct (dst_ip, dst_port) from one source within 10 s, at most one alert per source per 10 s | `PortScan`, `source=rule`, confidence 1.0 |

## Detection CSV

`data/phase1_detections.csv`:

| timestamp | src_ip | dst_ip | attack_type | score | severity | source | flow_key |
|---|---|---|---|---|---|---|---|
| 2023-11-14T22:14:10.190Z | 127.0.0.1 | 127.0.0.1 | PortScan | 1.0 | high | rule | TCP\|127.0.0.1\|55555\|127.0.0.1\|20 |
| 2023-11-14T22:14:20.299Z | 127.0.0.1 | 127.0.0.1 | anomaly | 0.991 | low | isolation_forest | TCP\|127.0.0.1\|60000\|127.0.0.1\|80 |

- The scan alert fires on the 20th distinct port probed (port 20, 0.19 s into the scan); the rest of the scan falls inside the same 10 s window, so there is one alert.
- The flood is flagged at confidence 0.991 (above 99.1% of benign training flows). As an unnamed anomaly below p99.9 it is severity `low` by design (D6). See [LIMITATIONS.md](LIMITATIONS.md).

## What this shows

- PCAP → flows → shared features → model trained on CICIDS2017 → alerts works end to end, and works on a fresh clone without the dataset (the model is committed).
- The scan rule covers what the Isolation Forest cannot: each scan probe is a 2-packet flow that looks like benign short traffic.
- The synthetic benign sessions are 20 near-identical flows, so "0 of 20 flagged" is not evidence of a low false-positive rate on real traffic.

## Design changes in Phase 1 (human-approved)

1. TCP flag counts dropped from the shared feature subset (9 → 5 features).
2. Isolation Forest flags by benign-score percentile instead of `contamination="auto"`; threshold taken from the confidence grid.
3. Hardening pass (D1–D6): parsing fixes, scan rule, severity tiers, sha256-checked committed model. See [the weak-spot design](superpowers/specs/2026-10-28-weak-spot-hardening-design.md).

## Reproduce

Detection needs no dataset:

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python backend/detect_offline.py --pcap tests/fixtures/sample.pcap --out data/phase1_detections.csv
```

Retraining the model needs `data/raw/cicids2017/MachineLearningCSV.zip` (official UNB download behind a registration form; 235,102,953 bytes, sha256 `c3f26274b36c837ccf28ffd2dbf4582941c30b3ee70a635c6e5b2f87c4727928`):

```bash
unzip -o data/raw/cicids2017/MachineLearningCSV.zip 'MachineLearningCVE/Monday-WorkingHours.pcap_ISCX.csv' -d data/raw/cicids2017/
.venv/bin/python backend/ml/train_baseline.py --csv data/raw/cicids2017/MachineLearningCVE/Monday-WorkingHours.pcap_ISCX.csv
```
